## 任务 A：优雅停机（约 40 分钟）

### 现状

`server/index.js` 用 `app.listen` 启动（文件末尾），**没有任何 SIGTERM/SIGINT 处理**。
`pm2 reload` 或 kill 时：进行中的评估（最长 30s+）被硬切，用户看到连接中断且
（在 01 完成前）额度已扣。

### 实现

```js
// index.js 末尾
const server = app.listen(PORT, HOST, () => { /* 现有启动逻辑原样 */ });

let shuttingDown = false;
async function shutdown(signal) {
  if (shuttingDown) return;
  shuttingDown = true;
  console.log(`[shutdown] 收到 ${signal}，等待进行中的任务完成...`);
  // 1. 停止接收新请求
  server.close(() => console.log("[shutdown] HTTP 已关闭"));
  // 2. 等待并发槽位清空（queue.js 导出 queueStats：{ active, waiting }）
  const deadline = Date.now() + 35_000;
  while (queueStats().active > 0 && Date.now() < deadline) {
    await new Promise((r) => setTimeout(r, 500));
  }
  // 3. 停止定时任务（startPurgeJob 若返回 stop 函数则调用；否则置全局标志）
  db.pragma("wal_checkpoint(TRUNCATE)");
  console.log("[shutdown] 退出");
  process.exit(0);
}
process.on("SIGTERM", () => shutdown("SIGTERM"));
process.on("SIGINT", () => shutdown("SIGINT"));
```

配套：`server/core/queue.js` 的 `acquire()` 在 `shuttingDown` 标志置位后直接
`reject(new Error("服务正在重启，请稍后再试"))`（需要从 index.js 或独立模块导出该标志，
建议放 queue.js 内部 `export function beginShutdown()`）。

### 验收

- [ ] 启动服务 → 发起一次评估 → `kill -TERM <pid>`（或 `pm2 reload`）→ 该评估跑完落库、
      历史可查；期间新请求收到 503/排队拒绝；进程在 35s 内退出
- [ ] 无进行中任务时 kill -TERM → 1 秒内退出

## 任务 B：SQLite 每日备份（约 30 分钟）

### 现状

数据全部在单个 SQLite 文件（WAL 模式），无备份。简历属用户敏感数据，文件损坏 = 全部丢失。

### 实现

在 `server/jobs/` 新增 `backup.js`，模式对齐现有 purge.js：

```js
import db from "../core/db.js";
import fs from "fs";
import path from "path";

const BACKUP_DIR = process.env.BACKUP_DIR || path.join(process.cwd(), "backups");
const KEEP = Number(process.env.BACKUP_KEEP || 7);

// better-sqlite3 原生在线备份 API，无需停服
export function runBackup() {
  fs.mkdirSync(BACKUP_DIR, { recursive: true });
  const file = path.join(BACKUP_DIR, `app-${new Date().toISOString().slice(0, 10)}.db`);
  if (fs.existsSync(file)) return file;   // 当天已有则跳过
  await db.backup(file);                   // 注意：db.backup 返回 Promise
  // 清理旧备份
  const old = fs.readdirSync(BACKUP_DIR).filter(f => f.startsWith("app-")).sort();
  while (old.length > KEEP) fs.unlinkSync(path.join(BACKUP_DIR, old.shift()));
  return file;
}
```

- 与 purge 任务同一调度器启动（`startPurgeJob` 所在位置加一个每日一次的 backup 定时）。
- `.gitignore` 加 `backups/`；`DEPLOY.md` 补一段"备份位置与恢复方法"（sqlite3 CLI 或直接替换文件 + 重启）。
- 单测：临时目录跑 runBackup → 文件生成、二次调用跳过。

### 验收

- [ ] 启动服务 → `backups/app-YYYY-MM-DD.db` 出现且可用 `sqlite3 ... .tables` 打开
- [ ] `npm test` 全绿

## 注意事项

- 备份文件含用户简历（敏感数据），`backups/` 必须进 `.gitignore`，且 DEPLOY.md 提醒
  服务器上该目录权限 700。
- 优雅停机的 35s 上限要小于 pm2 的 kill 超时（`kill_timeout` 默认 1600ms——需在
  DEPLOY.md 的 ecosystem 配置里写 `kill_timeout: 40000`，否则 pm2 会提前 SIGKILL）。
