# 02 错误文案映射：技术错误不透传给用户

**优先级**：P2　**预估**：1 小时　**前置依赖**：无（建议在 03 之前做，避免冲突）

## 现状

- `server/routes/evaluate.js:367` 等处把 `error.message` 原样返回给前端，
  用户会在 toast 里看到 `fetch failed`、`ECONNRESET`、`LLM 请求超时` 等技术词。
- `server/index.js` 末尾的全局错误中间件已经做了兜底（未知错误 → "服务器内部错误，请稍后重试"），
  但**路由层 catch 里透传 message** 的路径绕过了这层保护。
- LLM 层（`server/llm/llm.js`）抛出的错误 message 是技术性的（超时/停滞/网络分类在
  `isRetryable`，:93 附近）。

## 目标

所有到达前端的 error 文案都是中文人话；原始技术 error 仍完整进服务端日志（排障能力不损失）。

## 实现步骤

### 1. 新建 `server/http/userMessages.js`

```js
// 按匹配顺序生效；命中即替换为用户文案
const RULES = [
  [/超时|timeout/i, "评估超时了，请重试一次"],
  [/ECONNRESET|fetch failed|network|socket|ECONNREFUSED/i, "网络波动，请稍后重试"],
  [/停滞| stalled/i, "生成中断了，请重试一次"],
  [/429|rate limit|繁忙/i, "模型服务繁忙，请一分钟后再试"],
  [/排队人数过多/, null],            // 已是人话，原样透传
];

export function userMessage(error) {
  const msg = String(error?.message || "");
  for (const [re, text] of RULES) {
    if (re.test(msg)) return text ?? msg;
  }
  return "服务暂时不可用，请稍后重试";
}
```

### 2. 替换路由层的透传点

`evaluate.js` 中所有 `error: error.message` / `res.status(500).json({ error: error.message })`
改为 `error: userMessage(error)`。涉及（以实际 grep 为准）：
`grep -n "error: error.message\|error.message }" server/routes/*.js`

- 每处替换**紧邻一行保留 `console.warn/error` 原始错误**（现有代码大多已有，确认不删）。
- 额度类错误（code 3001）的 message 来自 `quotaMessage`，已是人话，走 userMessage 的
  透传规则即可（不会被兜底改写——如果不放心，在 RULES 前加 `if (error.code === 3001) return error.message`）。

### 3. 单测 `server/__tests__/userMessages.test.js`

- 各规则命中 → 对应中文文案；
- 未知错误 → 兜底文案；
- code=3001 → 原样透传。

## 验收标准

- [ ] `grep -n "error: error.message" server/routes/` 无结果
- [ ] `npm test` 全绿；`npm run acceptance` 17/17
- [ ] 手工验证：把 LLM baseUrl 改成不可达地址 → 前端 toast 显示"网络波动，请稍后重试"，
      服务端日志仍有原始 `fetch failed`

## 注意事项

- 不要改前端 `src/lib/api.ts` 的错误解析结构（它读取 `error` 字段），只改服务端写入的值。
- 验收脚本（scripts/acceptance 相关）若断言了某些错误文案，同步更新断言。
