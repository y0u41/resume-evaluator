# 05 前端拆分与报告解析器单测

**优先级**：P3　**预估**：1 天　**前置依赖**：建议在 03 完成后做（服务端稳定后再动前端）

## 现状

- `src/pages/Result.tsx` 966 行：报告解析调用、九节渲染、匹配对照条、追问面板、
  下载、分享、编辑评分全部混在一个文件里。
- `src/lib/report/report.ts`（报告文本解析器）**没有单测**。ADR-0007 的核心决策
  （保持文本报告格式，靠"解析降级率"量化指标决定是否追加机器可读块）依赖这个解析器的
  质量可度量——目前无法度量：改一版 prompt 后，无法回答"解析质量有没有变差"。

## 目标

1. 解析器有 ≥ 15 个真实样本的回归单测（**先做，价值最高**）。
2. Result.tsx 拆到 ≤ 300 行，按已有自然边界切组件。

## 实现步骤

### 第一步：解析器单测（先做，约 2 小时）

1. 通读 `src/lib/report/report.ts`，列出它解析的输入形态（`【】`分节、`|` 匹配行、
   评分徽章等）。
2. 收集测试样本：
   - 来源 A：本地 dev.db 的 `evaluations.report` 字段里取真实历史报告（最真实）；
   - 来源 B：手写边界样本——正常 9 节、缺 1-2 节、节标题格式漂移（少【/多空格）、
     匹配行 `|` 缺失、纯文本无格式（完全降级）、超长报告、空字符串。
3. 新建 `src/lib/report/__tests__/report.test.ts`（vitest 已配置，参考
   `server/__tests__/` 组织方式；确认 vitest 配置包含 src，若只含 server 需在
   `vitest.config` 补 include）。
4. 每个样本断言：解析出的节数、每节标题、匹配项数量、降级时不抛错且返回可展示结构。
5. 若解析器有 bug（样本暴露），**修解析器，不改样本期望**，修复单独 commit。

### 第二步：Result.tsx 拆分（约 3-4 小时）

按现有自然边界切，新组件放 `src/components/result/`：

| 新文件 | 迁移内容 |
|---|---|
| `ReportView.tsx` | 九节报告渲染 + 降级纯文本展示 |
| `MatchBar.tsx` | 匹配对照条（若 Result 内是独立段） |
| `ObjectivePanel.tsx` | 客观分/评分徽章/objective 展示 |
| `FollowupPanel.tsx` | 追问输入与问答列表 |
| `ResultActions.tsx` | 下载/分享/收藏/编辑操作区 |

Result.tsx 保留：路由参数处理、数据获取、任务状态、顶层状态编排。

约束：
- **纯移动，不改逻辑**——迁移与重构分开 commit；
- props 类型从 Result 现有 state 推导，类型放各组件文件内；
- 不动 `src/lib/api.ts`、`src/lib/tasks.tsx` 的接口。

## 验收标准

- [ ] `wc -l src/pages/Result.tsx` ≤ 300
- [ ] 解析器单测 ≥ 15 个样本，`npm test` 全绿（注意：前端测试与服务端测试同一 vitest run）
- [ ] 手工冒烟：正常报告、格式漂移报告（可临时改 prompt 生成）、分享页——渲染与迁移前一致
- [ ] `npx tsc --noEmit` 通过（若项目有此检查）

## 注意事项

- Result.tsx 近期有大改动（收款码、objective 等），拆分前先 `git log --oneline -10 -- src/pages/Result.tsx` 了解最近变更，避免基于过时理解。
- 分享页 `src/pages/ShareView.tsx` 若复用了 Result 的渲染逻辑，抽出后两处统一引用
  ReportView，防止以后两套渲染漂移。
- 测试样本中的真实简历内容含个人信息——样本入库前脱敏（替换姓名/电话/邮箱）。
