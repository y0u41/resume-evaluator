# 08 补充优化建议（备忘，不在本轮强制执行）

> 这些是审查中发现、但优先级低于 01-07 或需要产品决策的建议。每条给出结论与理由，
> 供后续迭代时取用。**实现 agent 不需要执行本文件。**

## 1. 事实修正记录（相对此前对话中的说法）

此前把 `/compare` 的额度检查表述为"形同虚设"，**不准确**。实际代码
（evaluate.js:425）在循环前有整包预检查 `used + jobs.length > limit`，超额会直接拒绝。
真实问题只是：循环内 ：465 的 `consumeQuota` 返回值被丢弃，预检查与逐 job 计数之间存在
并发竞态（理论上另一请求同时消耗额度时可小幅超额）。01 文档的处理方式（整包预检查
保留 + 逐 job 走 withQuota）已覆盖该竞态窗口。

## 2. 支付对账自动化（有付费用户后优先做）

当前闭环：收款码 → 用户填邮箱 → 管理员人工批准。付费用户 > 10 人后建议接入
自动对账（微信/支付宝当面付、或爱发电/面包多 Webhook），触发器：周处理申请 > 20 笔
或出现第一起漏单投诉。管理员手动批准 + 07 的高亮是过渡期正确方案。

## 3. PRO 到期提醒（转化续费的低成本手段）

PRO 用户剩 7 天时，QuotaBanner 或报告页出一次性提示"PRO 将于 N 天后到期，可在
升级页续费"。数据已有（`/api/quota` 返回 daysLeft），纯前端改动，半天。
触发时机建议：`daysLeft <= 7 && daysLeft > 0`，dismiss 记忆 key 按天（模式复用
QuotaBanner 的 todayKey）。

## 4. 关键词库的 SEO 页面补内链

`server/seo/keywordPages.js` 生成的岗位关键词页之间目前可能是孤岛。每页底部加
"相关岗位"链接（同前缀/同行业，SQL LIKE 即可），提升爬虫抓取深度。SEO 有真实流量
后再做（目前 cold-start 门槛未达到，页面尚未发布）。

## 5. LLM 成本护栏（防刷兜底）

`llm_usage` 已按用户记录成本。建议 admin 页加一行"昨日总成本"，并设
`DAILY_COST_ALERT_YUAN` 环境变量：单日估算成本超阈值时启动日志 WARN。不做硬拦截
（会伤正常用户），只做告警。触发时机：注册用户 > 50 或出现第一次成本异常日。

## 6. 报告质量回归（改 prompt 必配）

现在改 `server/llm/prompt.js` 靠人工看效果。建议建立 5 份固定脱敏简历 + 3 份 JD 的
评测集，prompt 变更后跑一遍，人工对比报告九节完整性与逐条改法质量，结论记入
commit message。工作量：评测集半天 + 每次对比 10 分钟。触发时机：第一次想调 prompt 时。

## 7. 依赖与供应链

- `npm audit` 从未跑过：执行一次，高危项修复，低危记录在案。
- 依赖锁定在 package-lock.json 已有；建议 DEPLOY.md 写明"部署用 `npm ci` 不用 `npm install`"。

## 8. 二人协作预备（如果未来有人加入）

当前仓库一人开发，以下债务在单人时无所谓、协作时爆炸，提前记录：
- 无 lint 配置（无 eslint/prettier）——协作前加，一次配置 + 一次全量格式化 commit；
- AGENTS.md 是给 AI 的约定，人类新人需要一份精简版 CONTRIBUTING（可从 AGENTS.md 派生）；
- 测试目前全在 server/，前端组件零测试——05 完成后若引入协作，再考虑 vitest + testing-library。

## 9. 数据冷启动后的产品杠杆（运营备忘，非代码）

- A/B 实验（GUEST_AB_LIMITS=3,5 / GUEST_AB_PREVIEW=800,1500）在配置后需要
  **单组 ≥ 100 次游客试用**才能下结论——按当前流量预估时间，避免提前读数。
- 两周复盘要看的 4 个数：各 A/B 组游客→注册转化率、注册→首次评估率、
  报告读完→追问率、每用户 LLM 成本（admin 页现成）。

## 10. 不建议做的事（明确排除，防止过度设计）

- ❌ 换 Postgres / 加 Redis：触发器未到（见 07 的表）。
- ❌ 报告改 JSON 输出：ADR-0007 已否决，触发器（解析降级率超标）未命中。
- ❌ 微服务化 / 拆分路由为独立服务：单机单进程是当前正确的形态。
- ❌ 前端状态管理库（Redux 等）：现有 Context + hooks 复杂度尚未失控。
- ❌ i18n：目标用户是中文应届生，无证据支持多语言需求。
