## 现状

`server/routes/evaluate.js`（965 行、14 个端点）中，SSE 流式处理样板重复了 5 份，
每份包含相同的 5 个要素：

1. SSE 响应头三连（Content-Type / Cache-Control / Connection）
2. 断连检测：`let clientClosed` + `res.on("close", ...)`
3. 安全写出：`safeWrite`（判断 writableEnded + try/catch）
4. 排队：`acquire((position) => safeWrite(queued 事件))` + `finally { release() }`
5. 异常收尾：abort 静默 / error 事件 + `done: true` / end

`grep -c "const safeWrite" server/routes/evaluate.js` = 5。
**实证伤害**：01 文档记录的 interview/directions 扣费顺序 bug 正是复制漂移的产物。

## 实现步骤

### 1. 新建 `server/http/stream.js`

```js
import { acquire } from "../core/queue.js";

// 创建一个 SSE 连接封装：断连检测、安全写出、排队、收尾
export function createSseConn(res) {
  let clientClosed = false;
  res.on("close", () => { clientClosed = true; });
  res.writeHead?.call || null; // headers 由 start() 统一设置

  const safeWrite = (line) => {
    if (clientClosed || res.writableEnded) return false;
    try { res.write(line); return true; } catch { return false; }
  };

  return {
    get closed() { return clientClosed; },
    start() {
      res.setHeader("Content-Type", "text/event-stream");
      res.setHeader("Cache-Control", "no-cache");
      res.setHeader("Connection", "keep-alive");
    },
    write(obj) { safeWrite(`data: ${JSON.stringify(obj)}\n\n`); },
    error(message) { safeWrite(`data: ${JSON.stringify({ error: message, done: true })}\n\n`); res.end(); },
    end() { if (!res.writableEnded) res.end(); },
    // 排队；失败时自动发 error 事件并 end，返回是否成功
    async queue() {
      try {
        const release = await acquire((position) => safeWrite(`data: ${JSON.stringify({ queued: true, position })}\n\n`));
        return release;
      } catch (error) {
        this.error(error.message);
        return null;
      }
    },
  };
}
```

### 2. 逐个路由迁移（一次一个，跑一次测试）

以 `/followup`（最简单）为第一个迁移对象，模式：

```js
router.post("/followup", async (req, res) => {
  const { resume, jobTitle, question } = req.body || {};
  // 同步校验仍走 400 JSON（在 SSE 开始之前，保持现状）
  if (!resume || !jobTitle) return res.status(400).json({ error: "缺少简历或岗位" });

  const conn = createSseConn(res);
  conn.start();
  const release = await conn.queue();
  if (!release) return;

  try {
    await withQuota(req.user, { isPremium: ... }, async () => {
      await followUpStream({ ..., onChunk: (chunk) => conn.write({ chunk, done: false }) });
      // 落库 / 计数逻辑
    });
    conn.write({ chunk: "", done: true, ... });
  } catch (error) {
    if (!isAbort(error)) console.warn("followup 失败:", error.message);
    if (!conn.closed) conn.error(userMessage(error));
    else conn.end();
  } finally {
    release();
  }
});
```

迁移顺序建议：followup → directions → interview → compare → evaluate（由简到繁）。
**每迁移一个跑 `npm test` + `npm run acceptance`。**

### 3. 保持不变的既有语义（迁移时逐条对照）

- evaluate.js:197 决策：客户端断开**不中止**服务端 LLM，跑完落库 → `conn.closed` 只影响写出，
  不影响 LLM 调用继续。
- abort 后静默 end，不发 error 事件（现状 evaluate.js:271-273 等）。
- 缓存命中分支（:172-195）在 SSE 之前直接返回，不经过 conn。
- `queued: {position}` 事件的字段名与时机不变（前端 `src/lib/tasks.tsx` 依赖）。
- compare 的 `progress: { index, total, title }` 事件保留。
